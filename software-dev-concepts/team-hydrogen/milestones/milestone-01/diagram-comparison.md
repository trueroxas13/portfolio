# DFD
A DFD might not be able to capture data flow in a large system. Although a DFD is great in illustrating the flow of data through a system, it frequently gets too complicated for a system of this size, with too many flows to follow for many entities. While it does the task, it is not straightforward. On the other hand, UML class diagrams and use case diagrams provide a more comprehensive picture of the system's structure and functionality in a simpler and easier-to-understand manner.
# UML Use Case Diagram
While a use-case diagram is great at showing how various actors interact with the system in different ways, and also displays the various tasks the system performs in order to fulfill its intended purposes, it suffers from being unable to portray the inner individual components that make up the system. Although it is useful to have a "bigger picture" of the system, the lack of the know-how of how everything gets implemented later is one of the main drawbacks of utilizing a use-case diagram. A use-case diagram is also fantastic at breaking down how exactly the system performs each of its tasks step-wise (with the help of use-case specifications). Overall, a use-case diagram is incredible for looking at a system and its interaction with various actors on a surface level. This alone is sufficient for its analysis. If we wished to look at things at a more in-depth level, then something like a DFD or even a class diagram would be suitable, though that would not provide an analysis of the system at a grander scale and the "big picture" would be missing.
# UML Class Diagram
Throughout the process of designing the class diagram I always found myself thinking about the details of how are we going to implement the system code-wise, which I am not sure if it is good thing since there are many steps and workflows that come before coding, despite the fact that we have to think "# steps ahead". However, the concept of modularization and assigning responsibilities felt to be more effective when applied through the class diagram, since certain methods and attributes can be extracted by looking for verbs/ behaviours and nouns. Moreover, extracting classes from the project's description felt more easier than extracting the elements of a diagram like DFD.
