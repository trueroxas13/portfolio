# Project
The iQVR project is a simulation of a real-life software problem where our team was given the opportunity to apply the concepts we have learned during lectures and labs. The project consisted of 3 major milestones. Milestone 1's main objective was to establish the foundation for the system's architecture and identify the relationships between its components. Milestone 2's process involved sequence diagrams development, further extraction of functional/ non-functional requirements, and user interface implementation. Finally, milestone 3 involved expanding/ enhancing our class diagram using design patterns, demonstrating the team's tasks timeline through gantt chart and dependency graph, and project reflection writing by each member.

## Challenges
 
1. Extracting information
    * With all the specifications which the IQVR system required the hardest part of this project was the first part. Reading it and extracting info and trying to distinguish between all the different statements and how they can be implemented, as things where just thrown into the document asking for alot in each paragraph but also being vague. 
    * An example of that is: 
      * The document mentions that online reporting is allowed only for accidents between two vehicles if the offending party accepts responsibility. It does not explain how the system should handle accidents involving multiple vehicles or unclear fault cases besides directing users to the police station. Should these be handled through the system in any way?
 
2. Capturing details
    * it felt like you can keep adding details but we also needed to keep it simple, managable for our group but also try and maximize when possible. Keeping that balance was difficult to maintain and sometimes you just needed to stop and refresh the ideas if they are managable to have at the end of the project.
3. Accurate requirement gathering
    * Based on my experience, accurate requirement gathering is crucial for the success of project such as iQVR. Maintaining thorough documentation, and frequently validating requirements have enabled me to provide systems that address needs, reduce rework, and remain on schedule. 
4. Meeting the Dealine
   * Completing a system such as iQVR in four months brings was pretty difficult as i had other projects i needed to worked on. Prioritizing features, dividing tasks into milestones, and ensuring clear communication have been vital to achieving these demanding deadlines. 
 
## Lessons
 
1. Scalability Considerations
    * Systems should be designed with both current and future needs in mind. We believed that the accident reports should be between `n` number of vehicles but that would be very difficult to manage in this system.
  
2. Documentation
    * Although all the details were given to us in a document it was all over the place. We needed to document things many times before we could start working.
    Such as brainstorming, Functional and Non-Functional, and capturing specifications.
    Most importantly Filtering.

3. Importance of Planning and Communication
    * I've learned that thorough planning and clear communication are essential for project success. A well-defined distribution of tasks, reworking certain aspects and improving them, communication made it possible to picture and well define 90% of the project.

4. Balancing Speed and Quality
    * Balancing speed with quality is tricky, but focusing on main project features first has helped me meet deadlines without sacrificing much stability. Surely we couldn't get everything and most likely not missed many aspects, but it seems great for a 4 months of work with all the other pressure.
